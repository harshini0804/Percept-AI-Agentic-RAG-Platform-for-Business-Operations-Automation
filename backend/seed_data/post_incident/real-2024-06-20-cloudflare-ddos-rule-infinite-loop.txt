# Incident: DDoS Mitigation Rule Exposes Rate-Limiter Infinite Loop
Date: 2024-06-20
Service: cloudflare-edge
Severity: P0
Root Cause Tag: software-bug

## Summary
A newly deployed DDoS mitigation rule exposed a latent bug in Cloudflare's rate-limiting system where flawed cookie validation logic caused HTTP request handler processes to enter infinite loops consuming 100% CPU. The issue propagated across data centers as the rule was applied globally.

## Timeline
- 14:00 UTC — DDoS mitigation rule deployed globally
- 14:05 UTC — HTTP handler processes begin entering infinite loops
- 14:10 UTC — CPU utilization spikes to 100% across affected data centers
- 14:20 UTC — HTTP 502 errors increase dramatically
- 14:30 UTC — DDoS rule identified as trigger; rule disabled
- 14:40 UTC — Infinite loop processes killed; CPU normalizes
- 14:50 UTC — Full service recovery

## Root Cause
The rate-limiting system had a bug in its cookie validation path: under certain input patterns, the validation function entered an infinite while loop instead of returning an error. This bug was latent because the specific input pattern was never generated by normal traffic. A new DDoS mitigation rule changed how certain request headers were parsed before being passed to the rate limiter, inadvertently generating inputs that triggered the infinite loop. Each affected request consumed a CPU core indefinitely, and under normal traffic volume, all available CPU cores were exhausted within minutes.

## Impact
- ~50 minutes of elevated error rates across Cloudflare
- HTTP 502 errors for Cloudflare-proxied websites
- CPU exhaustion on edge servers in affected data centers

## Mitigation
- Immediate: disabled the DDoS mitigation rule; killed infinite loop processes
- Short-term: fixed the cookie validation infinite loop bug
- Long-term: added timeout enforcement on all request processing paths; implemented fuzz testing for rate-limiter inputs

## Lessons Learned
1. Input validation functions must have bounded execution time — no infinite loops.
2. New rules can trigger latent bugs by generating novel input patterns.
3. Request processing must have hard CPU time limits per request.
4. Fuzz testing against rate-limiting and validation code paths catches infinite loop bugs.
