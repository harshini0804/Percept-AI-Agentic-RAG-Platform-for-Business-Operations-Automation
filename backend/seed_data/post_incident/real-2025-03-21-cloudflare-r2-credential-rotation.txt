# Incident: Credential Rotation Deploys to Wrong Environment
Date: 2025-03-21
Service: cloudflare-r2
Severity: P0
Root Cause Tag: deployment-error

## Summary
During credential rotation for the R2 storage service, the engineering team accidentally deployed new storage credentials to the default environment instead of production by omitting the --env production flag. This caused the R2 Gateway to fail authentication once old credentials were removed from the actual production environment.

## Timeline
- 10:00 UTC — Credential rotation procedure begins
- 10:05 UTC — New credentials deployed with missing --env production flag
- 10:10 UTC — Old credentials removed from production
- 10:11 UTC — R2 Gateway fails to authenticate with storage backend
- 10:15 UTC — R2 API errors spike globally
- 10:25 UTC — Missing flag identified; credentials redeployed correctly
- 10:35 UTC — R2 service fully restored

## Root Cause
The R2 engineering team's credential rotation procedure required deploying new credentials using a CLI tool with an --env production flag. The default environment (without the flag) was a staging environment. The team deployed the new credentials without the flag, so they went to staging instead of production. When the old production credentials were revoked as part of the rotation, the production R2 Gateway had no valid credentials to authenticate with the storage backend. All R2 operations failed until the credentials were correctly deployed to production.

## Impact
- ~25 minutes of R2 object storage unavailability
- All R2 read/write operations failed globally
- Applications using R2 for storage experienced errors

## Mitigation
- Immediate: redeployed credentials with correct --env production flag
- Short-term: changed CLI default to production environment
- Long-term: implemented credential rotation automation that eliminates manual flag specification; added pre-rotation validation that confirms credentials are accessible in the target environment before revoking old ones

## Lessons Learned
1. CLI tools should default to the safest or most common environment, not a test environment.
2. Credential rotation should verify new credentials work before revoking old ones.
3. Destructive operations (credential revocation) should have a grace period where both old and new credentials are valid.
4. Automate credential rotation to eliminate human flag-specification errors.
